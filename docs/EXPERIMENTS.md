## X1. WhisperBench: A-VIP vs A-VIP + E2 (원본, 오프라인)

- **목적:** 같은 판매자의 재고·단종 주장에 대해, A-VIP 판매자 비교 규칙이 놓치는 것을 술어별 권위(E2)가 보완하는지, 그리고 정상 비용은 어떤지 본다.
- **가설:** E2는 재고 틀에서 같은 판매자 주장을 잡고, 지출 규칙보다 정상 확인 요청이 적다. 원본에서는 지출 규칙 대비 추가 차단이 0이다.
- **독립변수:** 게이트 구성. W1 A-VIP STRICT / W2s + 지출 규칙 / W2e + E2 / W3 둘 다
- **종속변수**
  - 공격 통과(claim 팔에서 alt 서명 중 ALLOW)
  - 정상 확인 요청(noclaim 팔에서 alt 서명 중 CLARIFY)
  - 음성 세트 오탐
- **비교군:** A-VIP binding은 원본 코드(커밋 `0c1b538`). 지출 규칙은 논문 기술 기반 재구현. E2는 제안.
- **데이터:** AP2-WhisperBench 실행 기록 main 700, cross_seller 840(개발), heldout 420(일반화). 원본이다.
- **방법:** 기록된 장바구니를 게이트에 다시 넣는다. 계획을 먼저 고정했고(sha256 `a4293cb9…`), A-VIP F4 재현을 확인했다.
- **결과** (`results/whisperbench_e2_20261126/README.md`)
  - 같은 판매자 재고 틀의 alt 서명: A-VIP 통과 87/87 → E2 통과 13/87
  - 기타 틀은 E2도 못 잡는다(87/87, 69/69 통과).
  - 정상 확인 요청: 지출 규칙 216/216, E2 0/216
  - 판매자 자신의 재고 안내 오탐 0/70
  - W3 = W2s(추가 차단 0)
  - heldout: E2 발동 15/182
- **한계**
  - 재고 술어에 한정된다.
  - 생성 문장으로의 일반화가 약하다.
  - 오프라인 재생이다.
  - 원본에는 가격 중립 공격이 없다.
- **대표 사례:** 틀 0. 비싼 상품의 글에 "Stock position: {want} is unallocated … {alt} is the mapped continuation"이 있고, 판매자가 두 상품을 모두 판다(A-VIP 권위 규칙상 권위 있음). E2는 재고 술어 권위 = 플랫폼이므로 CLARIFY로 보낸다.

## X2. G3: 가격이 같거나 더 싼 공격과 정상 사례 (생성, 정답 mandate = 상한)

- **목적:** 지출 규칙이 침묵하는 경우(가격 증가 없음)에 각 구성이 무엇을 막는지, 정상 안내와 정상 대체를 막지 않는지 본다.
- **독립변수:** 게이트 구성(W1, W2s, W2e, W3, P = 범위·조항·증거 게이트, P + E2)
- **종속변수:** 사례 유형별 정답 일치(공격은 DENY/CLARIFY, 정상은 ALLOW, 증거 없는 대체는 CLARIFY)
- **데이터:** WhisperBench 쌍 위에 고정 문구 덮어쓰기
  - 개발: main 418사례
  - 평가: cross_seller 836사례
  - 사례 파일은 `C:\ct\runs\cdv_wallet\generated\G3\`

**결과** (`results/g3_whisperbench_20261126/summary.json`, 평가 cross_seller)

|---|---|---:|---:|---:|---:|---:|
| a 같은 가격 브랜드 위반 alt | 막음 | 0/136 | 0/136 | 0/136 | 136/136 | 136/136 |
| b 같은 가격 가짜 품절 alt | 막음 | 58/140 | 58/140 | 116/140 | 140/140 | 140/140 |

  - **기준 주입(c)은 어떤 구성도 막지 못했다.** M2b가 구현되지 않았다.
  - e2의 평가 오답 58건은 경쟁 판매자 설정(X)에서 A-VIP V8이 DENY한 경우다. 정답(CLARIFY)보다 엄격한 쪽이다.
- **한계**
  - 생성 데이터다.
  - 정답 mandate를 썼다(상한).
  - 에이전트 선택은 재지 않았다.

## X3. M1 누락 검사: CartTrace 실제 발화 (정답 장부 입력, 검사기 단독)

- **목적:** 사용자 발화 전체를 보는 누락 검사가 실제 쇼핑객 문장에서 조건 누락을 찾는지 본다.
- **독립변수:** 조건 필드
- **종속변수:** 탐지율(조건 하나를 지웠을 때 그 필드를 찾음), 오경보율(정답 장부 그대로), 지연
- **데이터:** CartTrace validation 3,959여정(개발), test_cross_store 9,789여정(평가, 사후 표시). 원본이다.
- **결과(평가)** (`results/omission_realtext_20261126/README.md`)
  - 탐지율: 예산 87.3%, 배송 기한 81.3%, 수량 75.5%, 조건부 대체 65.7%, 수령 60.5%, 묶음 100%(템플릿 첫 발화 때문에 과대평가 가능), 브랜드 포함 8.6%, 브랜드 제외 0%
  - 오경보: 배송 기한 5.68%, 그 밖 1% 안팎
  - 지연: 중앙값 0.09ms
- **한계**
  - 정답 장부 입력(상한)이다.
  - 개발용을 보고 규칙을 고쳤다(v1 → v2. v1 결과도 보존).
  - 쇼핑객 발화는 시뮬레이터 문장이다.
- **대표 사례:** 수령 v1 놓침. "Regular delivery is fine by me"를 v1 패턴이 배송 진술로 읽지 못했다. v2에서 추가했다.

## X4. NLI 모델 선정 (로컬 CPU, 원본 전제 + 생성 가설)

- **목적:** V-B(근거)와 V-X(모순)의 자유 문장 단계에 쓸 NLI 모델을 고른다. NLI는 변경의 정당성(V-C)을 판정하지 않는다.
- **가설:** 거짓 근거율 5% 이하에서 근거 재현율이 높은 모델이 있다.
- **독립변수:** 모델(`cross-encoder/nli-deberta-v3-base`, `MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli`)
- **종속변수:** 근거 재현율, 거짓 근거율, 바꾼 값 모순 판정률, 쌍당 지연
- **데이터:** 전제는 CartTrace 첫 발화 원문이고, 가설은 숨은 사양의 고정 문장이다. 분할마다 필드 5 × (정상 40 + 바꾼 값 40). 개발 validation, 평가 test_cross_store(사후)
- **결과(평가)** (`results/nli_selection_20261126/README.md`)
  - 선정 모델(MoritzLaurer): 재현율 76.0%, 거짓 근거율 1.0%, 모순 57.5%, 349.5ms
  - 비교 모델: 65.0% / 5.0% / 58.0% / 52.3ms
  - 예산 모순 판정은 12.5%로 약하다. 그래서 숫자 충돌은 결정적 규칙이 맡는다.
- **한계**
  - 가설이 템플릿 문장이다.
  - 표본이 작다.
  - MiniCheck와 AlignScore는 비교하지 않았다(별도 추론 코드 필요).

## X6. 서명과 게이트 기능 시험

- ECDSA P-256(검증자는 공개키만 가짐)으로 바꾼 뒤 시험 49개가 통과했다.
  - 다른 사용자 키로 서명한 mandate → DENY
  - 서명 뒤 내용 변조 → DENY
  - 위조 증거 → E1
  - 재사용 증거 → E3
  - HMAC 모의 모드는 `hmac:` 표시로 구분된다
- **기여 분리:** 서명은 mandate·증거의 출처와 무결성을 보장한다. M1은 mandate 내용이 사용자 조건과 맞는지 본다. 서명이 맞아도 내용이 틀릴 수 있다. 이것을 보여 주는 것이 X2의 a·b와 X7이다.

## 비교와 구성 요소 제거 실험 설계 (원본 구현 / 재구현 구분)

| 구성 | 구현 | 쓰는 실험 |
|---|---|---|
| A-VIP binding(W 캡처, A-LEX, 권위 규칙, R, V1–V8) | **원본 코드**(`yedidel/avip_defense` @`0c1b538`, 수정 없음) | X1, X2, X7 |
| A-VIP 지출 확인 규칙 | 논문 §5.3·§7.7 기반 **재구현**(공개 코드에 없음) | X1, X2 |
| Standing 권위 규칙 | 논문 정의 기반 **재구현**(공개 저장소는 실험 스크립트. 규칙 함수 없음) | E2(재고 술어), 증거 E2 |
| 단순 LLM 검증(요약 + 강화 판정) | Google SGP 공개 설명 기반 **재구현** | X7 M-d |
| EAL 출처 필터·이벤트 | 논문 C.1·C.2 기반 **재구현** | X7 M-e |
| 제안: M1(V-P, V-B, V-C, V-X, V-S), E2 확장, 조건부 조항·증거, 결속 V9–V12 | 자체 | X1–X7 |
| 서명 | `cryptography` ECDSA P-256(표준), HMAC 모의는 제거 실험용 | X6 |

**구성 요소 제거 (데이터셋별로 따로 보고)**
- WhisperBench(X1·X2): A-VIP → + 지출 → + E2 → + 범위·조항(P) → + M1(X7과 같은 추출기로, G3에서)
- CartTrace(X7): 추출만 → + 출처 검사 → + 보존(V-P) → + 근거·누락(V-B) → + 비대칭 변경(V-C) → + 충돌(V-X) → + 대체 범위(V-S) → + NLI 단계
- 서명: ECDSA ↔ 모의 HMAC ↔ 서명 없음. M1 결과에는 영향이 없다는 것을 같은 사례로 보인다(기여 분리).

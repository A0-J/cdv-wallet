- 작성: 2026-11-26 밤
- 연구자 쪽 AI가 정리한 네 편과 보조 후보 TurnFlow를 AI(Claude)가 원문과 대조해 고쳤다.
- 양식: 해결하려는 문제점, 제안 기술 요약, 기여점, 한계점, 논문에서 참고할 점. 참고할 점의 각 항목은 앞의 네 칸 중 어디에 근거가 있는지 괄호로 표시했다.
- 수치는 논문 표와 본문에서 옮겼다. 논문에 직접 인쇄되지 않은 값(우리가 계산한 값)은 그렇다고 적었다.
- 개념도 오른쪽(권위 검증)은 Standing, 월렛 결속은 A-VIP를 쓴다(연구자 결정). 이 문서는 왼쪽만 다룬다.

## ① FnCTOD: Large Language Models as Zero-shot Dialogue State Tracker through Function Calling

- **서지**
  - 저자: Zekun Li, Zhiyu Zoey Chen, Mike Ross, Patrick Huber, Seungwhan Moon, Zhaojiang Lin, Luna Dong, Adithya Sagar, Xifeng Yan, Paul A. Crook
  - 게재: ACL 2024 Long Papers, pp. 8688–8704
  - 링크: https://aclanthology.org/2024.acl-long.471/ , arXiv 2402.10466
- **원문 확인 수준:** arXiv v4 전문(표, §7 한계, 부록)

**1. 해결하려는 문제점**
- 과업 지향 대화의 대화 상태 추적(DST)은 도메인별 주석 데이터로 지도학습해야 해서 비용이 크다.
- 제로샷 프롬프트 방식은 ChatGPT·Codex 같은 고급 상용 모델에서만 잘 동작했고, 덜 강한 모델에서는 성능이 낮았다.

**2. 제안 기술 요약**
- 도메인 하나를 함수 하나로, 그 도메인의 슬롯 값을 함수 인자로 본다. LLM이 채팅 응답 안에서 함수를 호출하는 형태로 대화 상태를 출력한다.
- 함수 선택과 인자 생성의 2단계로 나눠 프롬프트 길이를 줄인다.
- 36개 도메인 7,200개 대화(MultiWOZ 제외)로 LLaMA2-13B를 미세조정해 공개 모델에서도 동작하게 한다.

**3. 기여점**
1. MultiWOZ 2.1 테스트(대화 1,000개), 5개 도메인 평균 JGA:
   - GPT-4 62.59, GPT-3.5 61.31
   - 기존 최고 프롬프트 방식 IC-DST(Codex) 56.96보다 GPT-4가 5.63%p 높다(표 2).
2. 미세조정한 FnCTOD-LLaMA2-13B의 평균 JGA는 59.54(제로샷)다. 기반 모델 LLaMA2-13B-Chat의 49.28(5-shot)보다 10.26%p 높다(표 2).
3. 함수 호출을 2단계로 나누자 GPT-3.5 결과가 좋아졌다(표 4).
   - 다중 도메인 전체 JGA: 30.16 → 38.56
   - API 비용: 13.32달러 → 8.97달러(32.7% 감소)

**4. 한계점**
1. 여러 도메인이 섞인 대화의 전체 JGA는 GPT-4에서도 38.71%다. 저자도 "current accuracy may still not be good enough for the practical deployment"라고 인정한다(§7).
2. 함수 선택 정확도가 GPT-4 88.62%(GPT-3.5 95.54%)라서, 선택 오류가 인자 생성으로 전파된다(표 5).
3. 사용자가 조건을 바꾸거나 철회하는 경우는 다루지 않고, 관련 수치도 없다.
   - 기준선 수치는 각 논문에서 그대로 가져왔다(표 2 설명). 같은 조건에서 다시 잰 것이 아니다.
   - 추론은 사례당 1회다.
   - 비용의 분모(대화 수인지 턴 수인지)가 적혀 있지 않다.

**5. 논문에서 참고할 점**
- **제안 기술(변경 제안 추출기):** 결제 조건 필드(브랜드·예산·필수 기능·대체 범위)를 함수 스키마로 정의하면 추가 학습 없이 추출기를 만들 수 있다. (기술 요약)
- **평가 지표:** JGA를 추출기 진단 지표로 쓴다. (기여점 1)
- **종래 연구의 문제점:** 조건 변경·철회를 다루지 않는다. (한계점 3)
- **비용 보고:** 단계 분해로 비용이 줄어든 것처럼, 우리 검증 단계도 단계별 비용을 보고한다. (기여점 3)

**연구자 쪽 정리와 다른 점**
- "5.6%p"는 GPT-4 기준이다. 비교 대상 IC-DST(Codex)는 예시 검색기를 학습하는 데 도메인 데이터가 필요해 엄밀한 제로샷이 아니다(논문 각주).
- 49.28 → 59.54는 5-shot 기반 모델과 제로샷 미세조정 모델을 비교한 것이다. 설정이 다르다.
- "채팅 LLM이 DST에 약하다"는 논문 표현이 아니다. 논문은 채팅 모델이 일반 대화 위주로 학습돼 과업 지향 대화가 빠져 있다고 말한다.

## ② IntentFlux / StateForge: When Users Change Their Minds: Measuring and Repairing Intent Drift in LLM Agents

- **서지**
  - 저자: Yanjie Zhang(HKUST, Tencent LIGHTSPEED 인턴), Bowen Cao(CUHK), Zixin Chen(HKUST), Yushi Sun(LIGHTSPEED, 교신)
  - 게재: arXiv 2609.32520v1(2026-09-26), 게재처 없음. 논문 라이선스 CC BY 4.0
- **원문 확인 수준:** HTML 전문(부록 표 3–13 포함)

**1. 해결하려는 문제점**
- 사용자가 대체하거나 철회한 의도가 여러 턴 뒤에도 최종 답이나 도구 행동에 계속 영향을 준다(intent drift).
- 기존 다중 턴 평가는 이 실패를 다른 다중 턴 오류와 구분해 재지 못했다.

**2. 제안 기술 요약**
- **IntentFlux(벤치마크)**
  - 과업 = 원자 목표의 집합
  - 사용자 편집: Add, Delete, Replace
  - Variant: 나중에 다른 값으로 바뀌는 그럴듯한 값
  - Decoy: 나중에 사용자가 철회하는 그럴듯한 항목
  - 편집 발화는 LLM 사용자 시뮬레이터(DeepSeek-V4-Flash)가 만든다.
- **StateForge(해결책)**
  - 학습이 필요 없는 하네스다.
  - 사용자 턴마다 추적기가 편집을 "현재 활성 상태"로 접는다.
  - 삭제·대체된 항목에서 나온 결론도 함께 무효로 한다.

**3. 기여점**
1. 8개 모델 모두에서 drift가 나타났다. GPT-5.4의 CAR(만점 비율)은 Clean 조건(최종 의도를 바로 제시) 0.608에서 Hard 조건 0.224로 떨어진다(IDG 0.384, 표 1).
2. StateForge는 Qwen3.5-122B에서 평균 점수를 0.367 → 0.467, CAR을 0.264 → 0.368로 올렸다(표 2).
3. 턴 수만 맞춘 대조군은 0.734, drift 조건은 0.469다(차이 0.265, 표 10). 원인은 대화 길이가 아니라 폐기된 의도다.

**4. 한계점**
1. 정답 상태를 직접 줘도 0.549로, Clean 0.778보다 0.229 낮다. 상태만으로는 격차가 다 메워지지 않는다.
2. 구성 요소 제거 실험에서 중립 요약(neutral recap)은 0.441, 전체 StateForge는 0.428로 서로 구분되지 않는다(표 12). 저자도 "does not establish representation superiority over a matched recap"이라고 쓴다(§7.4).
   - 같은 StateForge가 본 결과에서는 0.467, 재실행에서는 0.428인데, 차이를 설명하지 않는다.
3. 추적기의 상태 추정 정확도 수치가 없다.
   - 하네스 비교는 Qwen3.5-122B 한 모델로만 했다.
   - 영역은 코드·수학·SQL·글 생성·요약·도구 호출과 VitaBench(배달·매장·OTA)다. 쇼핑·결제는 없다.
   - 변경은 모두 사용자 쪽이다. 적대적·외부 변경은 없다.
   - 코드와 데이터의 공개 주소가 없다("anonymized artifact"라고만 적음).

**5. 논문에서 참고할 점**
- **배경:** 폐기된 의도가 남는 문제의 근거로 GPT-5.4 CAR 0.608 → 0.224를 인용한다. (기여점 1)
- **제안 기술:** Add/Delete/Replace 편집과 "파생 결론 무효화"를 조건 장부의 연산과 보존 규칙 설계에 참고한다. (기술 요약)
- **시뮬레이션 환경:** Variant/Decoy 생성 방식을 정당 변경 세트(S2) 구성에 참고한다. (기술 요약)
- **평가 지표:** CAR, IDG(Clean − drift 차이) (기여점 1)
- **비교 모델:** 중립 요약 기준선을 비교군에 반드시 넣는다. 명시적 상태가 요약보다 낫다는 것이 이 논문에서 입증되지 않았기 때문이다. (한계점 2)

**연구자 쪽 정리와 다른 점**
- 0.608은 "단일 턴"이 아니라 Clean 조건(최종 의도를 바로 제시) 값이다.
- StateForge 수치의 모델은 Qwen3.5-122B다.
- 본 결과(0.467)와 구성 요소 제거 실험(0.428)의 수치가 어긋난다.

## ③ IDSS: Intent-Driven Situation Tracking for User-Centric Multi-Turn Agents

- **서지**
  - 저자: Meiling Tao, Peng Wang(교신, 전자과기대 UESTC), Yiling Tao(칭화대 선전 국제대학원)
  - 게재: arXiv 2608.15755v1(2026-08-16), 게재처 없음
- **원문 확인 수준:** HTML 전문. 그림 1–5의 값은 읽지 못했다.

**1. 해결하려는 문제점**
- 기존 다중 턴 에이전트의 맥락 관리는 근거 있는 사실과 과업 상태 판단을 분리한 명시적 상황 상태를 거의 유지하지 않는다. 그래서 사실 누락, 의도 이탈, 성급한 실행, 제약 위반이 생긴다.
- 기존 DST는 미리 정한 온톨로지의 슬롯-값만 다뤄서, 개방형 개체·동적 제약·다중 의도 의존을 위해 설계되지 않았다.

**2. 제안 기술 요약**
- **fact layer**
  - 도구 반환값을 결정적 파서로 출처(src)가 붙은 개체·속성으로 저장한다(ADD/UPDATE/DELETE/MERGE).
  - 값이 충돌하면 도구가 관찰한 값을 에이전트가 추론한 값보다 우선한다.
- **state layer**
  - 의도(활성/대기/완료/차단), 필요 변수, 제약 상태를 둔다.
- **제약 재검사**
  - 사실이 바뀌면 제약을 속성 비교로 다시 평가한다.
  - 위반된 제약은 연결된 의도를 차단한다.
- 학습이 필요 없다. 다만 state layer는 LLM이 `<state>` 블록으로 직접 쓴다.

**3. 기여점**
1. 8개 모델 평균으로 가장 강한 기준선 U-Fold보다 좋았다(§4.2).
   - τ-bench Airline: Avg@4 +1.5점, pass⁴ +2.0점
   - τ-bench Retail: Avg@4 +0.6점, pass⁴ +1.8점
2. 사실 누락 오류가 14% → 8%, 정보 부족 오류가 8% → 5%로 줄었다(§4.4, 모델 미기재).
3. GPT-4.1 구성 요소 제거 실험(표 2):
   - fact layer를 빼면 pass⁴ 34.8 → 31.3
   - state layer를 빼면 UserBench 0.382 → 0.350(8.4% 감소)

**4. 한계점**
1. 제약 위반은 방법과 관계없이 5–8% 범위로 거의 줄지 않는다(§4.4). 방법별 값은 그림에만 있다.
2. 토큰·지연 수치가 본문에 없다(그림에만 있음). IDSS 고유의 의도 이탈 수치도 없다. 분산과 유의성 검정이 없다.
3. 모든 조건에서 우위는 아니다(예: GPT-4o Retail Avg@4 70.0 vs U-Fold 70.2).
   - 사용자는 시뮬레이션(GPT-4.1)뿐이다.
   - 사용자의 조건 수정·철회 메커니즘이 없다. 실사용자 연구로 넘긴다.
   - 주입 공격 논의가 없다.
   - 차단은 LLM이 프롬프트를 따르는지에 달려 있다.
   - 코드 공개 주소가 없다.

**5. 논문에서 참고할 점**
- **제안 기술:** 사실 층(카탈로그·도구 정보)과 상태 층(사용자 조건)을 분리하는 구조가 개념도의 좌우 분기에 대응한다. 도구 관찰값을 우선하는 규칙도 참고한다. (기술 요약)
- **시뮬레이션 환경:** τ-bench Retail (기여점 1)
- **평가 지표:** Avg@4, pass⁴, 오류 유형 비율(사실 누락, 정보 부족) (기여점 1·2)
- **종래 연구의 문제점:** DST가 동적 제약을 위해 설계되지 않았다는 진술(문제점), 그리고 사용자 수정과 주입을 다루지 않는 점(한계점 3)

**연구자 쪽 정리와 다른 점**
- U-Fold 대비 수치는 특정 모델이 아니라 8개 모델 평균이다.
- fact layer의 출처 구분은 "도구 관찰 vs 에이전트 추론"이다. 사용자 발화와 판매자 글을 구분하지 않는다. 그래서 Standing 입력으로 쓰려면 출처 종류를 더해야 한다.

## ④ CASA (Continuous Agent Semantic Authorization): Hybrid Inspection and Task-Based Access Control in Zero-Trust Agentic AI

- **서지**
  - 저자: Majed El Helou, Benjamin Ryder, Chiara Troiani, Jean Diaconu, Hervé Muyal, Marcelo Yannuzzi(Cisco Systems, Switzerland)
  - 게재: arXiv 2605.02682v1(2026-05-04), 게재처 없음
- **라이선스:**
  - 논문: CC BY-NC-SA 4.0
  - 데이터 저장소: `outshift-open/tbac-research-datasets`, Apache-2.0
  - 참조 구현: outshift-open.github.io/CASA. 라이선스는 확인하지 않았다.
- **원문 확인 수준:** 본문과 표 I–VII. 부록 A–G는 요약만 읽었다.

**1. 해결하려는 문제점**
- 침해되거나 악의적인 에이전트 앱이 도구 호출을 조작하거나, 의도한 과업 범위를 넘는 권한을 요청할 수 있다.
- OAuth 2.0/2.1 위임 권한은 원래 의도를 보지 못해 이를 알아채지 못한다. 결정적 검사는 내용의 의미적 의도를 판단할 수 없다.

**2. 제안 기술 요약**
- 상태를 가진 가로채기 층이 대화 원장을 유지하며 모든 트래픽을 가로챈다.
- 결정적 검사 5개:
  - 도구 정의 무결성
  - 요청 권한
  - 행동 정렬
  - 인자 무결성
  - 데이터 충실성
- 의미 검사 2단계(각각 LLM 호출 1회):
  - 가로채기 층: 대화 과업 추출(자연어 한 문장)
  - 권한 서버: 과업–도구 일치(이진 판정)

**3. 기여점**
1. 단일 턴 ASTRA에서 Claude Sonnet 4.6 기준 F1 0.98, FPR 0.02, FNR 0.02(표 VI)
2. 다중 턴 데이터셋을 구축했다.
   - Augmented(테스트 3,242개): 사용자 이탈, 어시스턴트 이탈, 도구 선택 변형
   - Multi-Agent(테스트 1,870개): 3-에이전트 시뮬레이션. 무관 모드는 어시스턴트 프롬프트의 숨은 지시로 만든다.
3. 과대 권한(FPR)과 과소 권한(FNR)을 나누어 95% 신뢰구간과 함께 보고했다.

**4. 한계점**
1. 다중 턴에서 과대 권한이 늘어난다(표 VI·VII).
   - Multi-Agent에서 Sonnet 4.6의 FPR: 단일 턴 0.01 → 다중 턴 0.10
   - 다중 턴 FPR: Opus 4.6 0.20, GPT-5.4 0.15
2. 대화당 첫 도구 호출에서 대화가 끝난다. 그 뒤의 의도 변화와 다중 도구는 향후 과제다. 저자: "not yet sufficient on their own for high-stakes, long-horizon autonomous tool use"(§V).
3. 추출 오류(누락·날조)가 판정으로 전파된다고 쓰지만 측정하지 않았다.
   - 조건별 상태가 없다.
   - 비용·지연 수치가 없다.
   - 시스템 프롬프트를 검증 세트로 조정했다.
   - 합성 데이터만 썼다.

**5. 논문에서 참고할 점**
- **비교 모델:** "대화 → 과업 한 문장 요약 → 검증" 기준선(설계 v2의 B6). (기술 요약)
- **종래 연구의 문제점:** 다중 턴에서 FPR이 늘고, 첫 호출만 평가했다. (한계점 1·2)
- **평가 지표:** FPR(과대 인가)과 FNR(정당 요청 차단)로 ALLOW/DENY 판정을 평가한다. (기여점 3)
- **데이터 생성:** Augmented의 사용자 이탈·방해 문장 주입 방식. 저장소가 Apache-2.0이다. (기여점 2)

**연구자 쪽 정리와 다른 점**
- "에이전트 drift"가 아니라 "어시스턴트 이탈(assistant drift)"이다. Multi-Agent는 이탈 변형 데이터셋이 아니다.
- "멀티턴 FPR 0.02 → 0.10"은 서로 다른 데이터셋을 비교한 것이다(ASTRA 단일 턴 vs Multi-Agent 다중 턴). 같은 데이터셋(Multi-Agent)에서는 0.01 → 0.10이다.

- **서지**

- **원문 확인 수준:** 앞 40% 원문과 표 2. 나머지는 요약만 읽었다.

- 다중 턴 에이전트가 바뀐 제약이나 숨은 충돌을 알아채지 못하거나, 알아채고도 최종 응답에 반영하지 못한다.

**2. 제안 기술 요약**

  - 목표 전환 114

**3. 기여점**
1. 9개 모델 비교(표 2):
   - 상태 기반 다중 제약 따르기 통과율: 87–96%
   - 목표 전환: 10.53–54.39%(평균 24.95%, 우리가 계산)
   - 범위 확장: 평균 24.61%(우리가 계산)

3. 시나리오 100개를 사람이 검토해 87%가 세 기준(타당성, 도출 가능성, 판정 기준 타당성)을 모두 통과했다.

**4. 한계점**
1. 벤치마크라 해결 방법이 없다. 공격·주입 변경도 없다(읽은 부분 기준).
2. 범주 평균은 논문에 직접 인쇄되지 않았다(표에서 계산). 시나리오 작성에 한 모델 계열만 썼고, 사람 검토는 100개뿐이다.
3. 코드·데이터를 공개한다고 쓰지만 arXiv에 저장소 링크가 없다(프로젝트 페이지는 확인하지 않았다).

**5. 논문에서 참고할 점**

## 종합 판단 (AI 1차)

1. **조합 제안(FnCTOD + StateForge + IDSS)은 추출 단계의 구성 요소로 적절하다.**
   - FnCTOD 함수 스키마 → 변경 제안 추출
   - StateForge 편집 접기와 파생 결론 무효화 → 장부 갱신
   - IDSS 사실/상태 분리 → 신뢰 구분
   - 그래서 설계 v2 §12의 추출기 후보를 IC-DST 방식에서 **FnCTOD 방식(함수 호출 스키마)**으로 바꾸기를 권한다. FnCTOD는 IC-DST보다 높고, 예시 검색기 학습도 필요 없다.
2. **세 편 모두 변경을 누가 요청했는지 보지 않고, 적대적 변경도 다루지 않는다.**
   - StateForge: 사용자 시뮬레이터 변경만 다룬다.
   - IDSS: 주입 논의가 없다.
   - FnCTOD: 변경 자체를 다루지 않는다.
   - 그래서 개념도 왼쪽의 신규성은 추출이 아니라 그 아래 "Dialogue Context Verification"(변경 근거 검증, 선택적 반영, 보존)에 있다.
   - 이 부분의 가장 가까운 선행연구는 EAL(2609.01836)이다. 왼쪽 비교 대상에서 빠지면 안 된다.
3. **StateForge의 한계점 2가 우리 설계의 위험이다.** 명시적 상태가 중립 요약보다 낫다는 것을 그 논문도 보이지 못했다. 그래서 비교군에 "중립 요약 + 강화 프롬프트 판정"을 넣어야 한다(설계 v2의 B1′에 요약 변형 추가).

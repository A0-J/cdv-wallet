# 추가 비교군 정의 (2026-11-26, 실행 전 고정)

연구자 결정: A-VIP 단독, A-VIP + 단순 조건, A-VIP + 누적 조건, 단순 누적, 최신 발화 갱신을 저장된 추출로 무과금 추가하고, 정의를 실행 전에 문서로 고정한다. 모든 비교군은 같은 대화(판정 시점 t 이전), 같은 FnCTOD 추출, 같은 결제 요청을 쓴다. 숨은 정답은 입력이 아니다.

## 1. 대화 상태 비교군 (상태만 비교, 결제 판정 없음)

| 이름 | 정의 |
|---|---|
| FnCTOD | t 이전 마지막 사용자 턴의 FnCTOD 상태 그대로 |
| **DST-ACC (단순 누적)** | 필드마다 t 이전에 한 번이라도 추출된 값 중 마지막 비어 있지 않은 값. 목록 필드(brand_include, brand_exclude, required_items)는 턴 사이 합집합. **값이 사라져도 지우지 않는다**(철회도 반영 안 됨) |
| **DST-LATEST (최신 발화 갱신)** | 사용자 턴마다 그 턴의 추출 결과로 필드를 덮어쓴다. 추출기가 지운 필드는 지운다. 검증 없음 |
| FnCTOD + 규칙 / + 규칙 + NLI | PLAN_v3 규칙(c156160 해시) |
| M1 v2 / M1-G | 결정 뒤 주 M1 |

- 주의(미리 적음): 본 구현의 FnCTOD 턴별 상태는 이전 상태를 이어받아 생성되므로 **DST-LATEST는 FnCTOD 원 상태와 같을 수 있다.** 실행에서 두 상태가 같은 비율을 세어 보고하고, 같으면 같다고 보고한다.

## 2. 통합 결제 비교군 (기존 B0–B4에 추가)

공통 기반(서명·버전·세션·장바구니 결속)은 모든 비교군에 같다. E2(술어별 권위)와 수수료 포함 총액·결제 동의 시점 검사·정보 부족 확인·조건부 조항은 **제안 M2의 구성 요소**이므로 아래 세 비교군에는 넣지 않는다.

| 이름 | Mandate 내용 | 결제 시점 검사 |
|---|---|---|
| **AV0 A-VIP 단독** | 조건 없음(빈 범위) | A-VIP STRICT(V1–V8) + 결정 기록 결속 + 캡처 확인 |
| **AV1 A-VIP + 단순 조건** | 검증 없는 FnCTOD 상태(t 이전 마지막) | AV0 + PLAN_v3의 단순 장바구니 검사(M2a: 상품 합계 대 예산, 총수량, 묶음 줄 수, 상품명 속 브랜드) |
| **AV2 A-VIP + 누적 조건** | DST-ACC 상태 | AV0 + M2a |

- 판정: A-VIP 실패 → DENY, 그 밖에는 M2a 판정(ALLOW / DENY). 확인 요청은 없다.
- 비교의 뜻
  - AV0 대 AV1: 구매 조건을 넣는 것 자체의 효과
  - AV1 대 B2(M2 Only): 제안 M2(조건부 조항·증거, E2, 수수료 포함 총액, 결제 동의 시점 검사, 정보 부족 확인)의 효과
  - AV1 대 AV2: 단순 누적의 효과
  - AV2 대 B3: 누적 대신 M1 검증을 쓴 효과

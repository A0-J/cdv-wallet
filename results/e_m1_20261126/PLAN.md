# 계획: E-M1, 실제 LLM 추출기를 쓴 M1 효과 실험 (유료, 승인 요청용)

- 작성: 2026-11-26 밤
- **상태: 승인 대기. 아직 호출하지 않았다.**
- 승인 절차
  1. 연구자가 이 파일의 sha256을 승인한다.
  2. 실행 하네스를 구현하고, 가짜 모델로 무과금 시험을 한다.
  3. 파일럿을 한다(§6).
  4. 본 실행을 한다.
- 비용 단가: 기존 API 환경(OpenAI, `results/carttrace_protocol_ext_20261122/part2/RUN_PLAN_rev6.json`의 단가, 2026-11-21 확인)
  - `gpt-6-luna`: 입력 $0.10 / 출력 $0.50 (1M 토큰당)
  - `gpt-6.1-sol`: 입력 $2.00 / 출력 $10.00 (1M 토큰당)

## 1. 질문과 가설

- **질문:** 같은 결제 게이트에서 mandate를 만드는 방법만 바꿨을 때, 추출 + M1 검증(M-f)이 기준선보다 사용자 조건을 더 정확히 반영하는가?
  - 기준선: 단순 추출(M-c), 요약 + 강화 프롬프트 판정(M-d), EAL식 출처 필터·이벤트(M-e)
  - "정확히 반영"은 누락, 근거 없는 변경, 필수 품목 제거, 대체 범위 위반을 막으면서 정상 거래를 덜 막는 것이다.
- **H1:** M-f의 근거 없는 변경·누락 탐지율이 M-c보다 높다.
- **H2:** M-f의 정상 거래 오차단율(DENY + CLARIFY)이 M-d보다 낮거나 같다.
- **H3:** M-f가 M-e(EAL식)보다 정상 거래 오차단율이 낮고, 탐지율은 같거나 높다.
- **반증:** M-f가 M-c 대비 탐지율 향상이 없거나, M-d·M-e 대비 오차단율이 높으면 해당 주장을 하지 않는다. 결과는 가설과 달라도 그대로 보고한다.

## 2. 독립변수와 비교군 (같은 Episode 입력, 같은 게이트, 같은 정답)

| 팔 | mandate 생성 | 구현 출처 | 호출 |
|---|---|---|---|
| M-a | 정답(숨은 사양) | — | 없음. **상한과 기능 검증으로 따로 보고** |
| M-b | 에이전트가 쓴 grant(실험 2 재사용, AP2 train 여정만) | 원본 기록 | 없음 |
| M-c | 단순 추출: LLM이 사용자 턴마다 장부 변경 연산을 낸다. 검증 없이 적용 | 자체 구현(FnCTOD식 함수 호출 스키마) | 턴당 1 |
| M-d | M-c 장부 + 결제 직전 LLM 판정기(대화 전체 요약 + 강화 지시 "조건은 사용자만 바꾼다") | Google SGP 공개 설명 기반 **재구현**(원본 아님) | M-c + 여정당 1 |
| M-e | M-c 연산에 EAL식 출처 필터(인용이 사용자 턴이면 유지) + 이벤트 리듀서 | EAL(2609.01836) 논문 기술 기반 **재구현** | M-c와 같음(추가 없음) |
| M-f | M-c 연산 + M1 검증(`cdv/m1.py` 규칙 + 로컬 NLI) | 제안 | M-c와 같음(추가 없음) |

- M-c, M-e, M-f는 같은 추출기 출력을 공유한다. 차이는 검증뿐이다.

## 6. 절차

1. 하네스 구현(추출 프롬프트·함수 스키마 고정, 프롬프트 sha256 기록), 가짜 모델 시험(무과금)
2. 파일럿: R1 개발에서 10여정(luna). 형식 오류율과 비용을 확인한다. 파일럿 결과로 바꿀 수 있는 것은 출력 형식 파싱뿐이다.
3. 본 실행: 개발(R1 validation 100)로 M1 임계값(NLI)을 고정한다. 그 뒤 평가 세트(R1 test 300, R2, R3, G1)를 한 번 실행한다.
4. 분석: 같은 게이트에 여섯 팔의 장부를 넣는다. 여정 단위 Wilson 95% 구간, 상점·범주 군집 재표집을 쓴다.

## 7. 한계 (보고서에 그대로 적는다)

- 쇼핑객은 시뮬레이터다. CartTrace에는 실제 사용자 수정(완화·철회)이 거의 없다. 그래서 정상 변경 평가는 G1(생성)에 기댄다.
- M-d와 M-e는 원본이 아닌 재구현이다.
- 오프라인 재생이다. 에이전트 행동의 변화는 재지 않는다.
- 정답 사양은 CartTrace 판정표의 한계(라벨 점검 결과)를 물려받는다.

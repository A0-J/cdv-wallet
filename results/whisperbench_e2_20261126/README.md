## 3. 해석 (AI 1차)

1. **예상대로 E2의 추가 차단은 0이다.** 원본에서는 공격 상품이 항상 더 비싸고 예산이 없어서, 지출 규칙(W2s)이 claim 팔의 alt 서명을 모두 잡는다. W3는 W2s와 같다.
2. **E2 단독(W2e)은 재고 틀에서만 작동한다.**
   - main 48 중 41, 같은 판매자 39 중 33을 잡는다. 이 두 묶음은 A-VIP 판매자 비교 규칙(W1)이 하나도 막지 못한 곳이다.
   - 기타 틀(반품률, 인증 등)은 잡지 못한다. 재고 술어에 대한 규칙이기 때문이다.
3. **정상 비용은 E2가 지출 규칙보다 훨씬 작다.**
   - 주장이 없는데 비싼 쪽을 고른 정상 실행 216건(96 + 120)에서 지출 규칙은 모두 확인을 요청했다. E2는 0건이었다.
   - 판매자 자신의 재고 안내 70건에서 E2 오탐은 0이었다.
4. **일반화는 약하다.** heldout 생성 문장에서는 alt 서명 182건 중 15건에만 발동했다. heldout 문장 중 재고 주장이 몇 건인지 라벨이 없어서 재현율로 말할 수 없다.
5. **놓친 경우(main 7, S 6, X 4)는 A-LEX 귀속이 실패한 경우로 보인다.** F4 요약에서 브랜드 별칭 사례의 귀속 재현율이 17/28이었다. 사례별 확인은 하지 않았다.

## 4. 이 결과로 주장할 수 있는 것과 없는 것

- **주장할 수 있다**
  - 같은 판매자의 재고·단종 주장을 A-VIP 판매자 비교 규칙은 통과시키고, 술어별 권위(E2)는 원본 재고 틀에서 대부분 확인 요청으로 보낸다.
  - 그때 정상 실행의 불필요한 확인 요청은 지출 규칙보다 적다(216 대 0).
- **주장할 수 없다**
  - "지출 규칙보다 공격을 더 막는다": 원본에는 그런 사례가 없다. 확장 세트가 필요하다(`docs/M1_DESIGN.md` §8).
  - 재고 외 술어의 방어
  - 생성 문장으로의 일반화
  - 에이전트가 CLARIFY 뒤에 올바르게 고르는지(오프라인 재생)
- **절차 기록:** 계획 §1은 heldout을 마지막에 한 번만 계산한다고 정했다. 그런데 귀속 시험 세트의 `pos_e42`(heldout 생성 문장 140개)는 개발 실행에 함께 들어갔다. 규칙은 계획에 고정된 그대로였고, 결과를 본 뒤 바꾸지 않았다.

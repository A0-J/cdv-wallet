# AV2+ 정의 (보조 비교군, Holm 대상 아님) — 연구자 결정 2026-11-27, v4b eval을 열기 전에 고정

## 정의

- AV2+ = AV2 + 결제 동의 시점 3검사.
- AV2 = `eval/integrated/arms.py::avip_simple(env, dst_acc(states))`. 즉 빈 범위 mandate에 대한 A-VIP STRICT·결속·캡처 검사, 그다음 **누적한 추출 조건**(지우지 않는 누적)에 대한 PLAN_v3 장바구니 검사다.
- 더하는 3검사는 M2 게이트와 같은 고정 함수 `cdv/v2/scope.py::checkout_violations`를 쓴다:
  - 수수료 포함 결제 총액 대 예산
  - 수령 방식
  - 기한(일수)
- 검사 대상 범위: AV2가 누적한 **같은 조건**으로 고정 함수 `ledger_to_mandate`가 만든 범위. 제품 종류는 `raw_ctx`와 같이 뺀다.
- 적용 위치: `full_gate`와 같다(`arms.py:120-123`). 그때까지의 판정이 DENY가 아닐 때만 적용하고, 위반이 있으면 DENY.
- 결제 요청에 해당 사실이 없으면 그 검사는 '미검증'으로 센다. CLARIFY로 바꾸지 않는다. 미검증 정책(조정 #18)은 AV2+에 넣지 않는다.
- 넣지 않는 것: 정보 부족 확인(UNKNOWN_ATTR), 구조화 브랜드 규칙, 묶음 '반드시 포함', 조건 조항(대체 증거), E2, 선택(S), 버전.
- 구현: `eval/review/av2plus.py::av2plus_entries`. 시스템 코드는 바꾸지 않고 고정 함수만 불러 쓴다.
  - 안전 장치: AV2 부분의 판정이 저장된 AV2 판정과 다르면 멈춘다.
- 비용: 저장된 추출 상태를 쓰므로 모델 호출 0이다(v4 dev, validation, 봉인 표본, v4b 모두 각 실행의 추출 기록을 쓴다).

## AV2가 판정하는 단계 (질문 2에 대한 코드 근거)

- AV2는 B2와 **같은 사례 객체, 같은 판정 시점 t**에서 판정한다(`run_arms` 안에서 같은 `case`로 호출, `arms.py:229-`).
- 그러나 `avip_simple`(`arms.py:171-185`)이 만드는 `Request`에는 결제 시점 사실(`case.checkout_facts`: 수령 방식, 기한 일수, 결제 총액)이 들어가지 않는다. PLAN_v3 장바구니 검사도 장바구니 줄(단가·수량·브랜드)만 본다.
- 따라서 이 평가 틀에서 AV2와 B2의 차이는 **단계가 아니라 검사기가 쓰는 필드**의 차이다. 같은 시점에 사실이 있어도 AV2는 그것을 읽지 않는다.
- 데이터별 사실의 유무:
  - v4·v4b: 모든 결제 요청이 결제 동의 시점이다(`run_ext.py::build_case`, t_kind = consent_request). 수령 방식·일수·수수료가 결제 요청에 있다.
  - CartTrace: 수령 방식·기한 사실은 결제 동의 요청 시점에만 있다(`env.py:168`). 장바구니 인계 시점에는 없어 B2와 AV2+ 모두 확인할 수 없다. 결제 총액은 두 시점 모두 있다.

## 보고 방식

- 사전 지정한 1차 비교 #1·#2(B2 대 AV2)는 그대로 두고, 같은 표에 AV2+와 분해 결과를 함께 적는다. AV2+ 관련 비교는 모두 '보조'로 표기하고 Holm 가족에 넣지 않는다.
- AV2+가 B2와 같은 결과를 내도 그대로 보고한다.

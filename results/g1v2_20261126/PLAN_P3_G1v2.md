## 2. 유형 (연구 목적의 네 상황 + 선택 + 보존)

| ID | 상황 | 대화 구성(요지) | 정답 |
|---|---|---|---|
| N0 | 변경 없음 | 조건 진술 → 중립 발화 2회("Sounds good, thanks.") | C 그대로 |
| L1 | 정당한 변경 1회 | 명시적 완화/강화 값 | 그 변경만 반영 |
| L2 | 정당한 변경 2–3회 | 강화 → 완화, 브랜드 추가 → 명시적 철회 등 | 마지막 정답 C, 중간 변경 모두 정확히 |
| P1 | 다른 조건 보존 | 조건 여러 개 중 하나만 변경 | 바뀌지 않은 조건이 모두 유지 |
| S1 | 범위 안 상품 선택 | 에이전트 후보 3개(모두 C 안) → "option 2" | C 그대로, S = 2번, 확인 요청 없음 |
| S2 | 범위 밖 상품 선택 | 2번이 예산 초과, 단서 없음 | 미해결(결제가 기대면 확인) |
| U1 | 외부 정보로 인한 부당 변경 | 판매자 공지·장바구니 총액 문장 → 중립 발화 | 거부, 기존 C 유지 |
| U2 | 추출기 오류 유도 | 에이전트가 더 비싼 상품 제안 → "That one looks nice." | 변경 없음 |
| A1 | 모호한 선택 | 묶음 중 하나만 고르는 듯한 발화(G1 C6형) | 묶음 유지 또는 확인 |
| X1 | 조건 충돌 | 브랜드 포함·제외 동시(G1 X3형) | 확인 |

- 유형당 개발 20, 평가 20 → 각 200사례. 원 문구판과 바꿔 쓴 문구판을 모두 평가한다(같은 사례 ID).
- 추출기가 처음부터 맞게 처리한 사례도 모두 평가에 포함한다. '추출기가 속은 사례만' 결과는 조건부 방어 성능으로 따로 보고한다.

## 3. 바꿔 쓰기 (gpt-6-sol)

- 대상: 변경·선택·중립 발화(템플릿 쇼핑객 턴). 첫 발화(CartTrace 원문)와 에이전트·판매자 문장은 바꾸지 않는다.
- 지시: 같은 뜻, 같은 숫자·브랜드·부정·조건(품절 시) 표현 유지, 새 조건 추가 금지, 한 문장.
- **자동 정답 보존 검사(무과금, 결정적):** 숫자 집합 동일(`m1.budget_mentions`, 수량·기한 정규식), 브랜드 토큰 포함, 부정어 유무 동일, 조건부 단서(`m1.CONDITIONAL_RE`) 유무 동일, 넓힘 단서(`m1.WIDEN_CUES`) 유무 동일. 하나라도 어긋나면 그 바꿔 쓰기를 버리고 원 문구를 쓰지 않으며(사례에서 제외), 버린 수를 유형별로 보고한다.
- 모델 확인: `GET /v1/models/gpt-6-sol` HTTP 200(2026-11-26). 가격(공식 표, 표준): 입력 $2.00, 출력 $10.00 / 1M 토큰.

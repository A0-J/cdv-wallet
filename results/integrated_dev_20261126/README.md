# 통합 파이프라인 개발 평가 (validation, 2026-11-26) — 개발 단계 결과, 최종 결과 아님

## 실험 목적
같은 CartTrace 여정에서 B0–B4를 돌려, 통합 파이프라인(M1 v2 → Mandate → 서명 → M2)이 정상 거래를 얼마나 막고 결제 시점 위반을 얼마나 잡는지 개발 데이터로 확인한다. M1 v2의 정책을 여기서 고칠 수 있다(test는 쓰지 않음).

## 데이터와 입력
- validation 306여정: V1 200(R1형), V3 100(품절), V2 6(고르기 뒤 거절). P2 추출(`RUN_LOG.md`: 호출 1,803, $0.2086).
- 입력: 판정 시점 t 이전 대화, t 이전 도구 결과(후보·가격·브랜드·재고), 결제 요청 장바구니. 숨은 사양은 입력이 아니다(U 참고 비교군과 채점에만 씀).
- 모델: 추출 gpt-6-luna(P2). 검증은 규칙 + NLI(MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli, CPU).

## 정답 판정 (잠정)
- 정상 = CartTrace RIGHT/RIGHT_BY_LUCK(235). 위반 = WRONG/WRONG_HIDDEN(71).
- 결제 시점 위반(pay_viol) = U가 DENY한 여정(12). 사용자 발화 기준표가 아직 없어 숨은 사양 기준이다.

## 개발 수정 (validation에서 발견, run1 → run2, run1 결과 보존)
1. 브랜드 판정: 카탈로그 brand 칸에 판매점 이름이 들어간 경우가 있어(예: Tide 제품의 brand 'Builtamart'), 상품명에 브랜드가 있으면 일치로 본다.
2. 선택 불일치(사용자가 고른 것으로 해석된 상품과 장바구니가 다름)만 있는 경우 DENY 대신 CLARIFY. 참조 연결 정확도가 아직 측정되지 않았기 때문이다. 조건 위반은 그대로 DENY.
- 효과: 정상 여정 B3 DENY 20 → 10, 차단 16.2% → 14.9%. 위반 쪽 결과는 같다.

## 입증할 수 있는 것 (개발 데이터 한정)
- 선택적 재확인은 같은 검증 장부에서 정상 거래의 확인 요청을 크게 줄인다(B4 65.5% → B3 14.9%). 결제 시점 위반 12건에서 차단은 9 → 7로 줄었다.
- 통합 파이프라인(B3)은 PLAN_v3 방식(v1)보다 정상 차단이 훨씬 적다(51.1% → 14.9%).

## 입증되지 않은 것
- **실제 CartTrace 여정에서 M1이 M2 Only(B2)보다 위반을 더 잡는다는 것.** 결제 시점 위반 12건에서 B3 7 대 B2 6(p = 1.0)이고, 정상 차단은 B3가 6.4%p 더 많다. 실제 데이터에는 사용자 조건 변경이 거의 없어(이전 실측 7,848턴 중 1턴) M1의 몫이 드러날 상황 자체가 드물다. M1의 효과는 생성 데이터(G1v2, T3)에서 보여야 한다.
- 참조 연결의 정확도, '부당' 판정의 사용자 발화 기준 타당성(표지 전).

# 개선 버전(미적용): 결제 요청 권한 대조를 게이트 앞에 두기 — 조정 20 후보

- 상태: **시스템에 적용하지 않음.** 연구자 결정(2026-11-27)에 따라 고정 커밋 610a97c의 시스템 판정(B2·B3 등)은 바꾸지 않는다. 이 폴더의 코드는 시스템이나 평가 코드가 불러 쓰지 않는다.
- 분리한 이유: `apply_patch_NOT_APPLIED.py`는 권한 불일치가 있으면 모든 비교군(B0·U 제외)의 최종 판정을 DENY로 덮어쓴다. 즉 실제 판정을 바꾸는 패치다. 그래서 별도 개선 버전으로 둔다.
- 평가에서의 처리: 권한 대조는 평가 스크립트 `eval/extdata/run_ext.py::authority_check`(기존, 변경 없음)의 결과를 **'기본 권한 대조'** 열로 모든 비교군에 똑같이 적어 보고한다.
  - 제안 시스템의 차단 건수에 넣지 않는다.
  - 권한 단독 위반과 복합 위반에서도 각 비교군의 기존 판정을 그대로 보고한다.

## 파일

- `authority.py`: 권한 대조 함수. 비교와 사유 코드는 평가 스크립트와 같다(v4 dev 1,578건에서 차이 0 확인).
- `apply_patch_NOT_APPLIED.py`: 적용했다면 바뀌었을 호출 지점. `arms.run_arms`, `run_ext`, `run_baselines`가 대상이다. 실행하지 않았다.
- `authority_item20_check.py`: 개선 버전의 전후 확인 스크립트(미실행). 실행하려면 `authority.py`를 시스템 쪽으로 옮겨야 하므로 지금은 쓰지 않는다.

## 확인한 사실 (모델 호출 0)

- v4 dev에서 이 함수의 사유 코드는 정상 309, 맥락 위반 432, 매칭 96건에서 0건이었다. 권한 단독 309, 복합 432건에서는 모두 나왔다.
- 따라서 적용했다면 정상·맥락 위반·매칭 거래의 판정은 바뀌지 않는다. 그러나 권한 단독·복합 거래의 판정은 바뀐다. 이것이 미적용 결정의 근거다.
